# Ruling GATE-INVERT-1

**Decision (Ahmad, 2026-11-02; the same lesson as the auth deny-by-default rule NZ-D10):** the `deploy-change` label is required for ANY changed file except an explicit allowlist of paths that cannot change how the Worker is built, installed or deployed: `src/**` and `web/src/**` (application code, which CI tests review), `docs/**`, root `*.md`, `test/**` except `test/deploy-change-label.test.ts`, and the brand image and font folders (`web/brands/<id>/public/**`, copied not executed). Everything else needs the label: `package.json`, every lockfile, `scripts/**`, `wrangler.jsonc`, every build or tool config at any depth (tsconfig, vite, postcss, tailwind, babel, browserslist, `.npmrc`), `.github/**`, `migrations/**`, `vendor/**`, `foundation/**`, `web/**` outside `web/src`, and any new kind of file. Two supporting checks: vite's PostCSS is pinned (`css: { postcss: {} }`) so a stray `postcss.config` or `.postcssrc` is never auto-discovered, and `test/deploy-change-label.test.ts` fails if a lockfile other than `package-lock.json` exists anywhere in the repo. The table test in that file covers nested configs and foreign lockfiles.

**Evidence:** the earlier list-of-deploy-files design failed open: each review found another file the build reads (nested PostCSS and Tailwind configs, `.postcssrc`, `.babelrc`, `.browserslistrc`, yarn, pnpm and bun lockfiles, `scripts/ci/**`, the label test itself). An allowlist fails closed: a file nobody thought of needs the label.

**Cost if wrong:** most PRs that touch anything outside application code, docs and tests need Ahmad's label (pre-approved per PR through the controller), which slows them down; the label check is advisory (it runs PR code), so it is a human checkpoint and not a hard gate.
