# Ruling STORE-STANDING-2

**Decision:** STORE-STANDING-1 stops spend only on an explicit `store.suspended` / `store.deleted`; silence from the Store fails open. STORE-STANDING-2 adds fail-closed on silence, behind `STORE_STANDING_STALE_REFUSE` (unset or `0` = off, the default; `1` = on). When on, a LINKED workspace refuses all spend (`isSuspended` true, `workspace_suspended`) and raises the P1 alert `store_standing_stale` when the last Store standing was received more than 24 h ago. A workspace with no standing yet is allowed for 24 h from its `store.linked` (for a workspace that predates the event, from the moment the switch is first seen on), then refused. An unlinked workspace is exempt.

**How:** every standing event received, including a repeat or one older than the last applied, stamps `store.standing_at` (local clock) in the workspace's SQLite; `store.linked` stamps `store.standing_anchor` and clears `standing_at`. The DO copies the env var into `store.standing_strict` on every wake so the synchronous gate (`standingStale` in `src/core/numbers/health.ts`, read by `isSuspended` and `suspensionState`) needs no env. 24 h = two missed 12-hourly heartbeats. The refusal is workspace-side only: it is not mirrored to D1 `suspended_*` (time passing triggers no write), so the Worker's own pre-check does not see it, but every send claim, campaign, AI and automatic reply does. The operator console (kill-switch card, `storeStandingAt` on `GET /operator/workspaces/:id/ops`) shows when standing last arrived.

**Enable condition:** ebda-store #851 live (the emitter and the 12-hourly re-send) AND at least one heartbeat observed per linked workspace in the console (`storeStandingAt` not null for every linked workspace). Until then the switch stays off: with no emitter every workspace would count as silent and spend would stop for everyone. Turning it off again (`0`) removes the gate on the next wake.

Cost if wrong: a Store outage or a stuck standing queue longer than 24 hours stops Chat spend for every linked merchant until standing events resume (or the switch is set to 0); a workspace that never gets a `store.linked` and predates the switch is anchored at enablement, so it gets one full window before it can be refused.
