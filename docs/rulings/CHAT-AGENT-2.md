# Ruling CHAT-AGENT-2

**Decision:** The merchant's declared facts reach the agent as trusted text, and nothing else may be quoted as a fact. `getStorePolicies` is read on EVERY turn (no cache: shipping, COD and returns are money-adjacent), rendered into the prompt and added to what the reply guard vouches for. A field the merchant never declared is rendered `NOT DECLARED`, so an amount the model invents is refused by the guard (`invented_fact`, handoff). A FAQ up to 3072 characters is read whole instead of through the vector index (which is empty in production today); a bigger one keeps the index and raises `agent_faq_not_indexed` while it is empty. Tone is three presets (`warm` default, `professional`, `playful`) added after the merchant's own persona, never replacing it.

**Evidence:** audit D1, D5, rows 29-32; `test/chat-agent-context.test.ts` (a fee the Store returned is quoted; a fee it did not return, a wrong fee and an undeclared store are all refused). Mutation check: removing the facts from the guard's trusted text turns "a shipping fee the Store returned can be quoted" red.

**Cost if wrong:** WA-GUARD-PROMISE-1 still rules, so a declared free-shipping threshold ("شحن مجاني") and the word "استرجاع" are refund/free-delivery PROMISES the merchant must switch on; until then those replies go to a person (the live eval counts them `handed_off_needlessly`). The model can still misread a correct fact in words the guard cannot check (a fee for the wrong zone with a matching number).
