# Ruling WA-404-1

**Decision:** an address Ebda WhatsApp does not serve answers a real HTTP 404 with Ebda AI Studio's shared "nothing here" page (the studio-pages renderer the Store hosts use), never the inbox shell with a 200. Static assets use `not_found_handling: "none"`; the Worker's `notFound` hands a GET/HEAD to the brand pack's `notFound` (`src/addons/ebda/not-found.ts`, Arabic by default, English by `Accept-Language` or `?lang=`, noindex, no-store, its own locked-down CSP). Any other method, and any `/api/` path, keeps the JSON 404. The one real deep link, the sign-in return `/auth/callback`, is handed the shell by the Worker. The renderer and brand are vendored byte for byte under `vendor/studio/` and sha-pinned in `test/vendored-artifacts.test.ts` (re-vendor both together with the Store). The white-label deploy template keeps the SPA fallback (its pack has no studio page).

**Evidence (2026-10-29 sweep):** `curl -s -o /dev/null -w '%{http_code}' https://wa.ebda.app/zzz-nope` returned 200 (the SPA fallback), a soft 404 search engines would index; Store ruling SUBDOMAIN-404-1 / 404-1b already serves this page on the other hosts. `test/studio-404.test.ts`.

**Cost if wrong:** a bookmarked path that only the old fallback served now shows the 404 page; the app itself reads no path other than `/` and `/auth/callback`, so nothing in the product depends on it.

**Amendment (2026-11-17, CH3):** the shell now reads its screen from the address (`web/src/lib/route.ts`), so the Worker also hands the shell to each screen path in `SHELL_PATHS` (`src/index.ts`: `/campaigns /templates /contacts /agent /bot /numbers /integrations /wallet /team /ops /chat/:id`). Every other unknown path still gets the studio 404. `test/shell-routes.test.ts`, `test/assets-config.test.ts` keep both lists equal. Cost if wrong: a path added to the web router but not to `SHELL_PATHS` 404s on refresh (the equality test fails first).

**Update (F8, 2026-11-23):** the page is now the foundation's `createStudioPages` shell (`foundation/studio-pages.ts`, lock-pinned) bound to the vendored BRAND; `vendor/studio/studio-pages` is removed. Same 404 status, same CSP (only the visit-count host is added, as before). The old page listed Ebda Chat under "coming soon"; the shell lists it as live and names CRM and ERP as the coming-soon rows. Bytes are pinned by `test/studio-404-shell.test.ts`. Cost if wrong: a re-vendor that changes the shell fails that pin instead of changing what Chat serves unnoticed.
