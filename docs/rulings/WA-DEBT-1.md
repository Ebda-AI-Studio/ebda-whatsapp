# Ruling WA-DEBT-1

**Decision:** Wallet debt past 2 x the overdraft limit stops spending for the workspace and alerts `wallet_debt_suspended` (P1). The ledger entry that caused the debt (delivery charge, Meta adjustment, chargeback) is always recorded in full and never refused. The debt has its OWN workspace flag (`billing.debt_hold`), independent of the operator's (`ops.suspended`) and the Store's (`store.hold`); `isSuspended` reads all three, and each clears on its own (a top-up back to `>= -limit` clears only the debt flag). D1 `suspended_at/suspended_reason` is derived from the flags by one helper, `syncSuspendedMirror`, used by every writer (reason = operator's, else the Store tag, else `wallet_debt`). A debt suspension pauses running / scheduled campaigns with the existing reason `wallet_empty` (queued pages parked; nothing resumes them). An operator suspension over a debt one is audited and counts as abuse for offboarding; `wallet_debt` never holds an erasure.

**Evidence:** `src/core/billing/engine.ts` (`debtGuard`), `src/core/ops/suspension-mirror.ts`, `src/core/ops/kill-switch.ts`, `test/billing-wallet-debt.test.ts` (debt + operator, debt + Store hold in both orders, campaign pause). Composes with STORE-STANDING-1 (#121). Review of #118 found three composition bugs with a shared D1 reason; deriving D1 from independent flags removes the class.

**Cost if wrong:** a merchant with a large legitimate chargeback cannot send (waiting utility sends fail instead of waiting) and sees paused campaigns until they top up; a limit of zero set by an operator makes any debt suspend.
