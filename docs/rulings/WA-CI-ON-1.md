# Ruling WA-CI-ON-1

**Decision:** PR CI is on and follows the Ebda CI pattern; deploys run from CI on a push to main (Ruling WA-DEPLOY-2, which replaced the manual WA-DEPLOY-1). A PR whose changes are all under `src/`, `web/src/` or `test/*.test.ts(x)` runs typecheck, the static guards (the `node` vitest project, in full) and only the `workers` and `web` tests its change reaches (`vitest --changed origin/<base>`); every push to main, and any PR touching a shared input (package files, `wrangler.jsonc`, vitest/tsconfig, `migrations/`, `test/setup.ts`, `test/helpers/`, the CI scripts and workflow) or any file outside those folders (docs, vendor, scripts), runs the full suite. The choice is `scripts/ci-affected.sh`; anything it cannot account for is `full`.

**Evidence (2026-10-29):** the "CI paused" line in `docs/launch/README.md` section 9 was stale: `ci` and `gitleaks` ran on every PR since 2026-10-25 (repo variable `EBDA_RUNS_ON` = `["self-hosted","umbra-ebda"]`, the Umbra runner for this repo online, PR #40 run green in 19m32s). Already in `ci.yml` and now pinned by `test/ci-workflow.test.ts`: `EBDA_RUNS_ON` with a hosted fallback (`ubuntu-latest`), no fork PR on the self-hosted runner, `cache:` for npm only when hosted (no remote Actions cache on Umbra), a per-PR concurrency group (newer push cancels), `timeout-minutes: 40` (raised from 25 on 2026-10-29: the full run measured 19-27 min on the shared VM), `npm audit`. Measured locally: with a one-line change in `src/core/billing/business-hours.ts` the affected run was 80 workers+web files / 1,164 tests; a docs change selects `full`; a push selects `full`.
- There is no lint step: the repo has no linter configured, and `tsc` (both projects) is the static gate. Adding a linter is a separate decision.
- Branch protection (require `ci` + `gitleaks` on `main`) cannot be set: GitHub answers 403 "Upgrade to GitHub Pro or make this repository public" on the Free plan with a private repo. `merge-gate.sh` is the gate.

**Cost if wrong:** a test that reads a file outside the module graph but inside `src/` (the static guards do) is covered because the `node` project always runs in full; a `workers` test that reads a non-imported file (e.g. a SQL fixture) would be skipped on a PR that only changes that file, and then caught by the full run on the merge to main. Cheapest fix then: add the path to the shared-input list in `scripts/ci-affected.sh`.
