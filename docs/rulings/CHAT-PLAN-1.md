# Ruling CHAT-PLAN-1

**Decision:** Chat has exactly one plan entitlement that a person can hit as a wall: the package's member (seat) limit (WA-SEATS-1). That is the only place the upgrade card is shown, with one action that opens the Store billing page (`<store admin>/stores/<id>/billing`, built from `BRAND.storeAdminUrl` and the session's `storeId`; no link when a brand has no linked store). Every other limit Chat shows is a balance or a pacing rule, not an entitlement: the wallet (marketing campaigns stop at zero, service messages ride a bounded overdraft), AI credits (assistant hands over to the team when they run out), and the new-conversation tier (display only). Those are topped up in the Wallet screen and keep their own banners; an upgrade card there would sell a package that does not fix the problem. When the Store exposes a new entitlement to Chat through the identity contract, it gets a card by passing `title/body/cta/href` to `UpgradeCard`; nothing else changes.

**Evidence:** `TeamScreen` (`seat_limit` refusal and `seats.overLimit`), `NoSeat` (staff, `over_limit`: the viewer cannot change the package, so no card), `i18n` wallet keys (`wOverdraft`, `wAiCreditsLow`, `tierLine`), WA-SEATS-1. Card anatomy mirrors the admin plan-refusal card (ebda-store #588); the component rule is recorded in the foundation design docs.

**Cost if wrong:** a limit that is really a plan entitlement would still read as a plain banner until someone passes it to `UpgradeCard`; and the Store billing URL shape (`/stores/:id/billing`) is taken from the coordinator, so a Store route rename breaks the link (the card then opens a 404 page in a new tab, nothing else).
